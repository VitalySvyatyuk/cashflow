# Cashflow — план разработки

Онлайн-версия настольной игры «Денежный поток» для одной компании: ведущий + N игроков.
Голосовая связь — во внешнем сервисе (Discord/Zoom/Telegram), в приложении её нет.

## 1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Backend | Python 3.12, Django 5 | по ТЗ |
| Realtime | Django Channels (WebSocket) + Redis (channel layer) | все экраны должны видеть ход фишки и бросок костей одновременно |
| API | Django REST Framework (лобби, создание игры, вход) | простые HTTP-операции |
| БД | PostgreSQL 16 | по ТЗ |
| Frontend | React + TypeScript + Vite | много «обычного» UI: карточка игрока, таблицы доходов/расходов, модалки, формы |
| Игровое поле | SVG внутри React + анимации через Motion (framer-motion) | поле статичное, движутся только фишки — игровой цикл не нужен |
| Кубики | `@3d-dice/dice-box-threejs` (3D, физика) | умеет показывать **заранее заданный** результат — значение генерирует сервер, клиент только анимирует |
| Звук | Howler.js | звук броска, покупки, зарплаты и т.п. |
| Инфраструктура | Docker Compose (postgres, redis, backend, frontend) | одинаково локально и на дроплете |
| Прод | DigitalOcean droplet 1 GB + Caddy (HTTPS автоматически) | самый дешёвый вариант, всё на одной машине |

### Почему не игровой движок (Phaser / PixiJS)
Phaser хорош, когда весь экран — это игра с игровым циклом. Здесь ~70% экрана — это
финансовая карточка, списки, кнопки и всплывающие карты, которые на Phaser делать неудобно.
Фишки, ходящие по клеткам, и кубики спокойно делаются в React (SVG + Motion + 3D-кубики).
Если позже захочется «вау»-эффектов на поле — поле можно перевести на PixiJS
(`@pixi/react`), не трогая остальной UI.

### Ключевой принцип: сервер — источник истины
Бросок костей, вытягивание карты, деньги игрока — всё считает Django.
Клиенты получают события по WebSocket (`dice_rolled {player, values:[3,5]}`,
`token_moved`, `card_drawn` …) и только **анимируют** их. Так нельзя смухлевать,
а переподключившийся игрок получает актуальное состояние.

## 2. Роли и экраны

- **Ведущий (superuser)** — логинится через Django-аутентификацию, создаёт игру
  (кол-во игроков: до 6, интерфейс рассчитываем в первую очередь на 4), получает
  код/ссылку для входа. Экран ведущего: всё поле, все игроки и их финансы,
  **очередь действий на одобрение**, лог событий, кнопки управления
  (старт, заморозка, передать ход, ручная корректировка денег, отмена действия,
  действие от имени игрока).
- **Игрок** — без регистрации: открывает ссылку/вводит код, пишет имя, получает
  токен (хранится в браузере, позволяет переподключиться).

### Одобрение действий ведущим
Ход обсуждается голосом, ведущий участвует почти в каждом действии.
Каждое действие игрока имеет политику:

| Политика | Примеры | Как работает |
|---|---|---|
| `auto` — игрок делает сам | бросок кубиков на своём ходу, «отказаться» от карты, завершить ход | применяется сразу, ведущий видит в журнале |
| `approve` — нужна санкция ведущего | купить сделку, продать актив, взять/погасить кредит, благотворительность, сделка между игроками | игрок отправляет заявку → у всех видна как «ожидает ведущего» → ведущий ✅/❌ (может поправить сумму) → сервер применяет |

Политики хранятся в одном месте (конфиг движка), чтобы их легко было перенастроить
после первых игр. Ведущий может откатить последнее действие.

### Заморозка игры
Ведущий нажимает «Заморозить» → `Game.status = paused` → у всех игроков экран
становится полупрозрачным (поле видно, но приглушено) с надписью «Игра на паузе»,
все кнопки неактивны, сервер отклоняет любые действия игроков. «Разморозить» —
возврат как было. Экран ведущего при заморозке остаётся активным
(ведущий может, например, поправить деньги).

## 3. Экран игрока (landscape, планшет/ноутбук/десктоп, от 1024×768)

```
┌───────────────────────────────────────────────────────────────────────┐
│ Игра #ABCD   Ход: Маша                            ⚙  🔊              │
├──────────────┬───────────────────────────────────┬────────────────────┤
│ МОЯ КАРТОЧКА │                                   │ ИГРОКИ             │
│ Профессия    │      ИГРОВОЕ ПОЛЕ                 │ ● Маша  $1 200 ←ход│
│ Зарплата     │   (внутреннее кольцо — крысиные   │ ● Петя  $3 400     │
│ Пассив.доход │    бега, внешнее — скоростная     │ ● Я     $2 100     │
│ Расходы      │    дорожка) + фишки               │                    │
│ Cashflow     │                                   │ ЖУРНАЛ             │
│ Активы ▸     │        [ 3D-кубики ]              │ Петя купил 100 акц.│
│ Пассивы ▸    │                                   │ Маша: Doodad -$200 │
├──────────────┴───────────────────────────────────┴────────────────────┤
│ [🎲 Бросить]  [Взять кредит]  [Погасить]  [Продать актив]            │
└───────────────────────────────────────────────────────────────────────┘
```

- **Поле — два концентрических кольца**: внутреннее — крысиные бега (~24 клетки),
  внешнее, охватывающее его, — скоростная дорожка (~40 клеток). Клетки показаны
  **только цветом** (без текста). Когда фишка встаёт на клетку, рядом всплывает
  её название/описание. Прикидка для экрана 1024×768: поле ~680 px по высоте →
  клетка внешнего кольца ≈ 50 px, внутреннего ≈ 55 px — помещается, до 6 фишек
  на одной клетке раскладываются веером.
- Выпавшая карта появляется **поверх поля** модалкой с цветом категории,
  названием, текстом и кнопками (Купить / Отказаться / Продать другому…).
  Её видят все игроки (с подписью, кто её вытянул), но действовать может только владелец.
- Клик по другому игроку — его карточка в режиме «только чтение».
- Активы/пассивы — раскрывающиеся списки.

## 4. Модель данных (первая версия)

- `Game` — код, ведущий, `max_players` (≤ 6), статус (lobby/running/paused/finished), чей ход, номер хода.
- `PendingAction` — заявка игрока на действие: тип, параметры, статус (pending/approved/rejected), кто решил, когда.
- `BoardCell` — дорожка (rat_race / fast_track), индекс, тип клетки, цвет, название, описание.
- `Player` — игра, имя, токен, цвет фишки, профессия, позиция, на какой дорожке, деньги, флаги (уволен, пропуск ходов, дети).
- `Profession` — название, зарплата, налоги, расходы, стартовые пассивы.
- `Card` — категория, цвет, название, текст, + параметры эффекта (цена, первый взнос, cashflow, тип актива) в JSON.
- `DeckState` — перемешанная колода для конкретной игры и указатель.
- `Asset` / `Liability` — что принадлежит игроку.
- `GameEvent` — журнал всех событий (для лога и восстановления состояния).

Категории (пока заглушки, позже заменим реальными картами):
Малая сделка (зелёный), Крупная сделка (синий), Рынок (жёлтый),
Траты/Doodad (розовый), Благотворительность, Зарплата, Ребёнок, Увольнение.

## 5. Шаги

1. **Каркас репозитория** — структура `backend/`, `frontend/`, `docker-compose.yml`
   (postgres, redis), `.env.example`, README, `.gitignore`.
2. **Django-проект** — настройки через env, Postgres, Channels/ASGI, DRF, админка.
3. **Модели + сидер** — модели из п.4, миграции, команда `seed` со случайными карточками, профессиями и клетками поля.
4. **Лобби (API)** — ведущий создаёт игру → код; игрок входит по коду с именем → токен; старт игры.
5. **WebSocket-слой** — consumer игры, авторизация по токену/сессии, рассылка событий, отдача полного состояния при подключении.
6. **Игровой движок (backend)** — бросок, движение, клетки, вытягивание карты, покупка/отказ, зарплата, кредиты, переход хода; очередь одобрений ведущего, заморозка, откат последнего действия. Чистые функции + юнит-тесты.
7. **Frontend-каркас** — Vite + React + TS, роутинг `/host/:code`, `/play/:code`, `/join`, WS-клиент, стор состояния (Zustand).
8. **Игровое поле** — SVG-поле из двух колец, цветные клетки, всплывающее описание клетки, фишки, анимация движения, переход фишки на внешнее кольцо.
9. **Кубики и звук** — 3D-кубики с результатом от сервера, звуки.
10. **Карточки** — модалка выпавшей карты, действия, финансовая карточка игрока.
11. **Экран ведущего** — обзор всех игроков, очередь одобрений, кнопка заморозки, журнал, ручные корректировки, управление ходом.
12. **Тесты и полировка** — pytest (движок + API + consumers), адаптив под планшет, переподключение.
13. **Деплой** — prod-compose, Caddy + HTTPS, бэкапы Postgres, дроплет на DigitalOcean.

## 6. Принятые решения

- Ведущий одобряет почти каждое действие; простые действия игрок делает сам (см. «Одобрение действий»).
- Ведущий может заморозить игру — экраны игроков становятся полупрозрачными и неактивными.
- Поле: крысиные бега внутри, скоростная дорожка — внешнее кольцо; клетки только цветом, текст — при наступании.
- Игроков до 6, интерфейс оптимизируем под 4.
- Интерфейс только на русском (без i18n, `LANGUAGE_CODE = "ru-ru"`).
